## 3. Реализованные сценарии

| Страница | Сценарии | Ожидаемый результат |
|---|---|---|
| Add/Remove Elements | Добавление двух элементов и удаление элемента | Количество кнопок `Delete` изменяется с 0 до 2 и затем до 1 |
| Checkboxes | Проверка начальных состояний и переключение обоих флажков | Первый флажок становится выбранным, второй — снятым |
| Dropdown | Проверка списка и выбор Option 1/Option 2 | В списке есть placeholder и две опции; выбранная опция отображается корректно |
| Inputs | Ввод чисел и использование стрелок вверх/вниз | Поле принимает число, `ARROW_UP` увеличивает значение, `ARROW_DOWN` уменьшает его |

Проект содержит четыре Page Object и четыре тестовых класса с позитивными и негативными проверками.
Для взаимодействия используются явные ожидания там, где элемент должен стать доступным.
Драйвер закрывается в `@AfterMethod(alwaysRun = true)`.

## 5. Surefire и CI-артефакты

Команда `mvn clean test` формирует каталог `target/surefire-reports`.
В нём находятся XML- и TXT-отчёты TestNG/Surefire с количеством тестов, статусами,
длительностью и стектрейсами ошибок.

Workflow `.github/workflows/maven-tests.yml` запускает тесты на JDK 17 в headless Chrome.
Даже при падении тестов workflow загружает каталог `target/surefire-reports` в GitHub Actions
как artifact `surefire-reports`.

## 6. Выводы и риски

Page Object отделяет локаторы и действия браузера от проверок, что упрощает сопровождение.
Явные ожидания уменьшают зависимость от скорости загрузки страницы. UI-тесты остаются
зависимыми от доступности внешнего сайта и версии Chrome, поэтому для диагностики следует
сохранять Surefire-отчёты из каждого запуска.

Дальнейшие улучшения: добавить скриншоты при падении теста, расширить набор страниц и
параметризовать запуск для Chrome/Firefox.
